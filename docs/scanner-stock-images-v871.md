# 強勢飆股與個股圖片來源修正（V8.7.1）

## 實際問題

1. 強勢飆股專用 DAILY_ONLY 路徑直接要求舊 Worker，沒有優先使用個股查詢已使用的官方歷史套件。2026-11-06 台積電的 Worker 日線為開盤2135、最高2140、最低2130，官方快照為2020、2195、2020。相同收盤2135不代表整根K線一致，原健康檢查停止是正確保護。
2. 泓瀚（4741）的 FULL Worker 有420根日線，其中2025-03-14、2025-03-26成交量為0；2026-11-06確實有成交。官方最近160根全為正成交量。舊提示未指明是哪一天，容易被理解成現在停牌。
3. 寶雅（5904）的官方短名為「寶雅*」，輸入選擇器顯示「寶雅 | 5904」。原圖片身分比對嚴格比較兩個字串，誤認使用者換股，因此阻擋無浮水印PNG。

## 修改

- `selection-data-v2.js`：新增共用 `acquireDailyBatch`，先核對官方SHA256套件、股票、市場、日期、OHLC及成交量契約；官方套件真正不可取得時，才對缺少股票執行原Worker路徑。官方資料已有衝突時不改用較容易通過的來源。已通過核對後，只清除同一筆舊取得錯誤，獨立身分或資料衝突仍保留。
- `strong-stock-ui-v47.js`：實際掃描與抽樣健康檢查皆接入上述函式，更新掃描快取版本，維持原選股及排名條件。
- `research-v83/stock-simple-report.js`：只忽略名稱尾端的星號註記；仍比對名稱與股票代號，不接受別家公司或不同代號。
- `tower-line-core.js`：零成交量提示標明實際日期，區分歷史日線與當日；不放寬驗證。
- `version-v50.js`、`index.html`、`market-outlook.html`：更新相關前端快取版本，顯示版本維持V8.7.1。
- `scripts/tests/wave-source-upgrade.test.cjs`、`scripts/tests/wave-report-plain.test.cjs`：涵蓋來源衝突、備援、舊錯誤重試、舊零量日線，以及5904名稱差異。
- `scripts/tests/elliott-browser.cjs`：點擊5904無浮水印按鈕並下載PNG，驗證4741舊零量情境，以及強勢飆股實際批次函式通過嚴格健康檢查。
- `scripts/audit-all-stock-images.cjs` 與 `.github/workflows/worker-contract-tests.yml`：分成四組，對每檔官方資料實際繪製並編碼波浪PNG及無浮水印PNG，逐檔核對身分、日期、OHLCV、圖片尺寸及裁切；保存完整JSON/CSV及4741、5904範例圖片。每200檔換一個瀏覽器頁面，釋放快取及Canvas資源。

## 驗證範圍與限制

逐檔稽核使用當期完整上市、上櫃官方套件，並共用正式程式的來源準備與圖片函式，沒有向1964檔股票重新大量呼叫Worker。真實短歷史、成交量口徑、價格斷點及DR限制仍保留；能輸出圖片不代表有資格進場，也不代表必須有1至5浪。

完整數量與結果以Actions的 `ALL_STOCK_IMAGES_AUDIT`、逐檔JSON/CSV及PR檢查為準。歷史績效仍缺少當時可得資料，維持研究模式，不宣稱預測改善。

本次更新GitHub Pages；未更動或部署Cloudflare Worker。直接呼叫舊Worker仍可能得到其正確拒絕的來源衝突；網站會優先使用已核對的官方日線，官方與備援皆不可用時保留阻擋。
