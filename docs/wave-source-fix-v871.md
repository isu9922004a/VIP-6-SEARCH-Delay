# V8.7.1 波浪資料傳遞修正

## 已重現的原因

1. 共用行情核對後的資料保留upstreamDataContract和原始日線，但刻意不冒用原始dataContract。波浪模組只接受後者，因此把已核對的共用資料誤判成資料不足，圖片沒有K線。
2. 主結果先顯示、補充研究稍後完成。過早產生波浪圖片時，沒有等待同次查詢的補充資料。
3. 原始回報常用stock欄位；輸入一致性檢查只讀code，可能誤擋代號查詢。
4. 原有價格斷點處理可能留下63根以上的有效研究區間。這個既有區間與完整來源指紋長度不同，不能當作任意刪改行情。
5. 圖上的問號原本表示轉折待確認，不是計算錯誤；標記及圖例改成中文「待確認」，虛線仍保留。

## 修正

- 在既有共用行情模組增加唯讀收據驗證，核對目前快照、股票、市場、收盤、來源指紋、標準化指紋及原始Worker契約。
- 波浪模組沿用此驗證，不自行重封契約、不放寬資料閘門。
- 僅允許原有inputWindow函式重算出來的價格斷點後區間；任意少一根仍阻擋。
- 同次查詢的補充資料共用同一個進行中的工作；圖片等待它完成。等待時改查另一檔股票，舊圖不可匯出。
- 代號檢查同時辨認stock與code。
- 資料確實不足時顯示具體原因，先不提供突破／防守價的下一步判斷。完整原因保留在圖片稽核資料與頁面狀態；圖片長文採摘要，避免超出版面。

大盤有K線但沒有數字，不一定是故障：目前轉折不符合標準數浪規則時仍保留原圖，不補畫不存在的1～5浪。此次不變更數浪、交易、排名、Kronos或原停損規則。

新增涵蓋共用收據、修改內容、過期快照、資料衝突、價格斷點區間的單元測試；瀏覽器追加等待資料、切換股票攔截及中文待確認標記。

另以台泥2026/11/06官方160根日線重現並驗證來源鏈路。既有全市場稽核加入波浪來源收據檢查與狀態統計，避免其他股票也被相同格式問題誤擋。

本次僅為Pages前端修正，不需要Cloudflare Worker部署。波浪績效仍未經完整歷史驗證，維持研究附層。
