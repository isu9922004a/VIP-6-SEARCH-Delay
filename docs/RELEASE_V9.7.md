## 新生 K0 與完成日

目標日來自已有完整年度覆蓋的官方交易日曆。台北 17:35 前不把當日暫存行情當盤後；週末與休市使用上一個可確認交易日。行情快照、研究 manifest 與目標日必須相同，母體筆數、兩市場筆數及股票集合必須吻合。

每檔先核驗 manifest SHA256、Worker 既有來源契約、逐日來源、OHLC、股數、完成狀態、價格口徑與交易日連續性。再從 `detect()` 全部事件選取 `side === BULL`、`k0Date === targetDate`、`k0Index === bars.length - 1`。不依賴 Kronos 成功或 `evaluate().event`。

原公式：`K3.high < K2.high < K1.high`，排除同時 `K3.low > K2.low > K1.low`；`K0.high <= K1.high`，生命線 `K3.low`。正式多方候選另要求 `K0.close >= lifeLine`。負距離仍保留原始事件，列 C 級及排除原因。

距離 `(K0.close / lifeLine - 1) * 100`，運算以十位小數消除浮點邊界雜訊，顯示兩位小數。0～3% 優先、3～6% 次選、超過6% 不列優先追價名單；門檻都是初始研究參數，不是驗證後的最佳條件。

## 商品、產業、成交金額與量能

商品須由官方 ISIN 主檔確認市場、ISIN、CFI `ESVUFR`、掛牌日期及普通股類別；不以代號開頭或名稱推測。未核驗／主檔缺項列資料不足。全額交割、變更交易、特殊處置由同日既有官方名單排除；停牌或未完成 K 棒不產生正式訊號。

產業使用官方公司主檔代碼 24～31、36，並與 ISIN 產業文字核對。只允許兩來源常見的「業」字尾差異；真正衝突不給資格。金融、營建、傳產、生技、綠能與白名單外產業排除；未知分類不猜測。

最低成交金額三千萬元，使用指定日 TWSE MI_INDEX／TPEx dailyQuotes 的實際成交金額，絕不以收盤×股數估算。來源的股票、日期、開高低收須與快照吻合。量比為當日股數／前5根完成日 K 平均股數；官方版本或快照股數不一致，不給量能分數、不輸出量能確認。

初版核對行情日為 2026-11-13，官方商品主檔更新日為 2026-11-15，兩個時間分開保留。這是目前資格核對，不能倒填成歷史時點資格。官方原始見證壓縮檔在 `scripts/fixtures/`，更新腳本及測試可重現其 SHA256。

專用成交金額工作於原行情更新成功後或平日排程執行，只更新新事實檔，再使用既有 Pages 程序發布。未取得新資料時保留舊檔；掃描器核對日期後將相關股票列資料不足。該工作的失敗不阻塞其他五套的原行情／推論更新。

1. 執行 `npm ci`、`npm test`、`npm run test:contract`、`npm run research:validate`。
2. 執行 `node scripts/audit-main-force-v97.cjs /tmp/v97-audit`、新瀏覽器測試、V9.5介面與V9.6大盤／原個股PNG測試。
3. PR「V9.7 主力生命線成本濾網」通過必要CI後，再同步最新main；禁止強推或覆蓋新資料。
4. 合併後走既有Pages發布工作，重新讀取正式版本與資產；實際掃描及產圖後才能宣告上線。不需要Worker部署。
5. 發現阻斷性問題，從最新main建立回復PR，對本版merge使用 `git revert -m 1 <merge SHA>`（squash則`git revert <commit>`），人工核對衝突，保留後續獨立更新。
6. 核對回復不更動 `data/`、`evidence/`、`config/`；不得reset／force-push。共用寶塔檔仍在，恢復舊入口與版本後即可回到原寶塔掃描。必要時停用新成交金額排程；不要回退正式行情或Kronos資料。
